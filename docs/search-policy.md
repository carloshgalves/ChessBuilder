# Search policy
Classic is the default and retains its exact legacy job settings and cache keys. Compact-v1 uses one MultiPV search for both best and played scores when the played root is present; otherwise it performs a forced search. With multiple candidates it uses one or two searches instead of two or three. Scores can differ because a MultiPV search is not equivalent to single-PV or forced search. Compact is opt-in, not calibrated, with separate job and cache identity. Existing results and checkpoints are not rewritten. Completed-game skipping compares the same policy. To compare on a local PGN: `python -m chessbuilder.benchmark_search sample.pgn --limit 50 --multipv 3`. The script measures cold search time, search count, absolute best-score deviation, classification agreement and expected-chance loss deviation without writing application data. It is intentionally not run automatically.

The replay prefers classic when coverage and depth are identical. If more than one saved analysis exists, use the analysis selector to inspect the exact job, without mixing its evaluations with another job. A deeper or more complete compact job can be chosen automatically under the usual coverage/depth rules. The benchmark uses the production policy function with a per-position isolated memo and records engine identity.
